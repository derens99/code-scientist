## Hypothesis

- Id: hyp-6208299229f5
- Status: accepted
- Elo: 1200.0
- Claim: Appending the instruction 'After implementing, act as an adversarial tester of your own code: enumerate the boundary and degenerate inputs the specification implies (empty inputs, single elements, ties, exact boundaries, invalid values, duplicates) and execute a check for each before finishing.' raises held-out pass rate versus a no-instruction baseline.
- Rationale: Held-out graders concentrate their discriminating power in edge cases, while the agent's default ad-hoc tests concentrate on the happy path it just implemented. An explicit adversarial-role instruction with a concrete category list redirects the agent's existing self-testing habit toward the input classes where graders actually differ, rather than adding a new artifact type. Mechanism: reweighting existing verification effort, distinct from checklist (extraction) and test-first (coverage-before-code).
- Origin: generation:debate_synthesis

### Assumptions

- Grader failures on baseline arms are concentrated in boundary and degenerate inputs
- The category list generalizes across task domains in the suite
- Executing per-category checks fits within trial limits

### Test Plan

- Experiment: Compare baseline coding-agent workflow against: Adversarial Edge-Case Enumeration Instruction Raises Held-Out Pass Rate.
- Metrics: pass_rate, regression_count, tool_calls, wall_time, cost
- Success condition: Candidate improves pass rate or regression count without unacceptable cost increase.

### Risks

- If baseline failures are requirement omissions unrelated to edge classes, redirecting test effort does not help
- The fixed category list may anchor the agent and crowd out task-specific edge reasoning
- Overlap with the agent's default behavior on tasks where it already tests boundaries, shrinking the measurable delta
