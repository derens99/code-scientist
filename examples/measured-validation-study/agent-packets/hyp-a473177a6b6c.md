## Hypothesis

- Id: hyp-a473177a6b6c
- Status: accepted
- Elo: 1232.0
- Claim: Appending the instruction 'Before writing any code, extract every requirement stated in the task and docstrings into a numbered checklist. Before finishing, verify your implementation against each numbered item and fix any item that fails.' raises a small coding agent's held-out-test pass rate versus a no-instruction baseline on spec-dense tasks.
- Rationale: Calibration probes show the small model already self-tests what it remembers, so residual failures come from requirements it never extracted from the spec. A forced enumeration step converts implicit spec coverage into an explicit artifact the agent can check against, targeting requirement omission rather than duplicating default self-testing. Checklist-style decomposition is a known scaffold for long-instruction compliance, but its effect on held-out grading of spec-dense coding tasks by small agent models is unmeasured here. Proximity synthesis from hyp-6744be5c7092: Appending the instruction 'Before declaring the task done, re-read the complete task description and every docstring one final time, and for each stated behavior confirm your implementation handles it; fix anything that does not.' raises held-out pass rate versus a no-instruction baseline. (similarity 0.978; method embedding_proximity).
- Origin: generation:failure_mode_decomposition

### Assumptions

- Held-out grader tests map one-to-one onto requirements stated in the task prompt and docstrings
- The agent complies with the appended instruction and actually writes the checklist
- Baseline failures are dominated by omitted requirements rather than algorithmic inability
- The extra enumeration step fits within the trial turn and time limits
- Omissions are recoverable at the end of a trial within remaining turn budget
- The agent genuinely re-reads rather than pattern-matching a confirmation
- Spec length fits comfortably in the agent's context at completion time
- The agent can translate stated behaviors into correct executable tests within trial limits

### Test Plan

- Experiment: Compare baseline coding-agent workflow against: Requirement-Checklist Extraction Instruction Raises Held-Out Pass Rate.
- Metrics: pass_rate, regression_count, tool_calls, wall_time, cost
- Success condition: Candidate improves pass rate or regression count without unacceptable cost increase.

### Risks

- Checklist writing consumes turns and wall time without improving pass rate on tasks the model could already solve
- The agent may write the checklist but not actually verify against it, diluting the effect
- On requirement-sparse tasks the instruction is dead weight and could distract
- Effect may be model-specific and not transfer beyond the tested model
- Late discovery of a missed requirement may exceed remaining budget to fix, converting omission into partial work with no pass-rate gain
- Weakest-dose intervention may produce an effect too small to detect at the experiment's sample size
- A perfunctory re-read yields no behavior change
- A misread requirement produces a wrong test that locks in the misreading (shared-blindspot failure)
